# Tempest exclude list for Cinder block-storage API tests.
#
# One regex pattern per line. Lines starting with # are comments.
# Blank lines are ignored. Patterns are matched against test IDs.
# Follows the same format as releases/2026.1/test-excludes/keystone.txt.
#
# Every group of patterns added here carries a tracked-by/re-evaluate-on pair
# directly above it so an exclusion does not silently outlive its cause:
#   tracked-by:      link to the issue that owns the exclusion
#   re-evaluate-on:  the condition that retires it, e.g. cinder-tempest-plugin
#                    > <the version the mismatch was observed on>
# Re-check every group on each plugin bump and drop the patterns upstream has
# fixed.
#
# The first CI run of PR #995 recorded the group below. Further groups land
# here the same way.

# tracked-by: https://github.com/C5C3/cobaltcore/issues/979
# re-evaluate-on: cinder-tempest-plugin > 1.22.0
# Snapshot tests that consult no [volume-feature-enabled] snapshot guard. The
# NFS backend runs under nas_secure_file_operations = true (#979 D3), which
# forbids snapshots upstream, so the operator renders nfs_snapshot_support =
# false and every snapshot these tests take ends in error. Core Tempest skips
# its own snapshot tests on the flag tempest.conf sets; these six read it
# nowhere. test_image_volume_dependencies_3 is here because it snapshots the
# volume it created from an image; _1 and _2 take no snapshot and stay in.
cinder_tempest_plugin\.api\.volume\.test_multiple_volume_from_resource\.CreateVolumesFromSnapshotTest\.test_create_multiple_volume_from_snapshot
cinder_tempest_plugin\.api\.volume\.test_volume_backup\.VolumesBackupsTest\.test_volume_snapshot_backup
cinder_tempest_plugin\.api\.volume\.test_volume_dependency\.VolumeDependencyTests\.test_delete_source_snapshot
cinder_tempest_plugin\.api\.volume\.test_volume_dependency\.VolumeDependencyTests\.test_delete_dep_chain
cinder_tempest_plugin\.api\.volume\.test_volume_dependency\.VolumeDependencyTests\.test_delete_dep_chain_2
cinder_tempest_plugin\.api\.volume\.test_volume_dependency\.VolumeImageDependencyTests\.test_image_volume_dependencies_3

# tracked-by: https://github.com/C5C3/cobaltcore/issues/1014
# re-evaluate-on: a compute driver other than nova's fake driver on this leg,
#                 or an NFS backend with nfs_snapshot_support = true
# Backups of an attached volume. Both tests attach the volume to a server and
# then create a backup with force=true. On the NFS backend cinder-volume
# serves that backup from a temporary clone, and cloning an in-use volume
# takes an online snapshot through Nova's assisted-snapshot API
# (cinder/volume/drivers/remotefs.py, _create_snapshot_online; the clone path
# calls _create_snapshot directly and so bypasses the nfs_snapshot_support
# guard that #979 D3 keeps at false). nova's fake driver does not implement
# volume_snapshot_create (nova/virt/fake.py has no such method, so the base
# driver raises NotImplementedError), so the snapshot never reaches 90 %,
# cinder-volume gives up after 600 s, and the backup sits in creating until
# tempest gives up at 300 s. Each test then spends another 300 s failing to
# delete the still-attached volume: 925 s per test, on the run and on the
# serial retry.
tempest\.api\.volume\.test_volumes_backup\.VolumesBackupsTest\.test_backup_create_attached_volume\[
tempest\.api\.volume\.test_volumes_backup\.VolumesBackupsTest\.test_volume_backup_incremental\[
